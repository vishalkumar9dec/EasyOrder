EasyOrder — Business Model Canvas

WhatsApp-first group ordering, checked out on Swiggy.
Phase 1 monetizes nobody. The return is Swiggy's GMV.

Key Partners

  • Swiggy — Food, Instamart, OAuth, checkout (and the MCP endpoint, when partner access lands)
  • Meta WhatsApp Business Platform
  • LLM provider — model ladder keeps cost and vendor risk controllable
  • Postgres / Supabase, container hosting
  • Dineout venues (Phase 5)

Key Activities

  • Agentic orchestration + guardrails
  • Swiggy MCP integration
  • Real-time chat → canvas session sync
  • Scheduling, degraded-vertical handling
  • WhatsApp policy + data retention

Value Propositions

  • Hosts: the coordination tax, removed. One message → one shared cart → host-controlled checkout.
  • Guests: edit your own items from a link. No app, no account.
  • Swiggy: higher AOV on its highest-value order type; Food + Instamart consolidated in one plan; fewer abandoned group carts; a WhatsApp-native surface the consumer app can't reach.
  • Companies (Ph. 2): team lunch with per-head budgets enforced before spend.

Customer Relationships

  • Conversational self-serve — first message is the first order
  • Host-mediated trust: guests hold scoped tokens, never check out
  • Saved lists → recurring commerce memory
  • Never autonomous — nothing charged without an explicit yes

Customer Segments

  • Group hosts — the one person compiling every order (flatmates, hostels, 6–10 person Friday plans)
  • Group guests — join by link, no signup
  • Corporate admins & team leads (Phase 2)
  • Swiggy — not a payer in Phase 1, but where the value lands

Key Resources

  • The agent harness — LangGraph graph, guardrails, deterministic fallback (the actual IP)
  • Provider-agnostic MCP client — real Swiggy is a URL + token
  • Session/cart store with host/guest token model
  • Skill-locked build harness — PRD, HLD/LLD, ADRs, runbooks, tests

Channels

  • WhatsApp Business number (primary)
  • Host-forwarded share link — the growth loop, at zero CAC
  • PWA planning canvas
  • Swiggy checkout via OAuth
  • Slack / Teams (Phase 6)

Cost Structure

  • LLM inference per parsed message — suppressed by a deterministic router (no model call for "hi") and a regex fallback
  • WhatsApp conversation fees — scale with sessions, not group size; replies go to the host
  • Infrastructure, compliance, one engineer + an agentic toolchain

Revenue Streams

  • Phase 1: none, by design — free consumer tool live
  • Phase 2: B2B SaaS subscription — corporate team-lunch coordination
  • Phase 3: service fee on occasion planning — food + groceries + Dineout
  • AOV uplift vs. solo carts hypothesis to validate
One rule holds the model together: EasyOrder never charges the group. Swiggy captures the cart. Built for the Swiggy Builders Program
