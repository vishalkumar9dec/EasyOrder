Authorization

Host token

host_<urlsafe32>, stored only as a SHA-256 hash. Sent on the private channel. Checkout, confirm and OAuth are host-only.

Guest token

guest_<urlsafe24>, safe to forward into a group. Read and cart edits only — checkout returns 403.

Web session

WhatsApp OTP → httponly cookie (ADR 0006). Scopes every /api/me/* read to one wa_id.

Enforced, not assumed

make security-smoke is release-blocking: guest checkout, guest confirm, cross-session tokens and host-token leakage all covered.

Adapters — every one has a Protocol and a mock

Database

AsyncPostgresDBAdapter over a shared asyncpg pool, or InMemoryDBAdapter for tests and local mock mode.

Swiggy

SwiggyMcpClient over Streamable HTTP, or the in-process MockSwiggyMcpClient. Selected by SWIGGY_CLIENT_MODE.

LLM

LLMIntentParser (OpenAI, strict JSON schema) with automatic fallback to MockIntentParser. Selected by LLM_MODE.

WhatsApp

MetaCloudWhatsAppSender (template → CTA → text) or MockWhatsAppSender, which captures sends in-process.

No Firebase anywhere. There is no Firestore adapter, no Anonymous Auth and no security-rule evaluation: ADR 0001 chose PostgreSQL, ADR 0006 replaced client auth with WhatsApp OTP, and ADR 0007 dropped row-level security in favour of authorization in the application, checked by security-smoke. The MCP client speaks Streamable HTTP, not stdio JSON-RPC.
