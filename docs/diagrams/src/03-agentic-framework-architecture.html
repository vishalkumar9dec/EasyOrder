Agentic Query Pipeline — LangGraph

One deterministic path. The model does exactly one job, and never the arithmetic.

Message → session

Inbound message

get biryani · 2 chicken biryani … under 2000 INR · hi

Intent router — before the graph, before any model

Regex → intent family. Greetings, history, saved lists, share, discovery and privacy commands are answered here for free; only real orders enter the graph.

① Input guardrails

Injection patterns rejected with HTTP 400. Emails, phone numbers and card numbers masked before the text reaches any model.

② Intent parser — the only LLM call

LLM_MODE=mock regex, or OpenAI with response_format: json_schema → budget, headcount, dietary tag, food and grocery queries. Any exception falls back to the deterministic parser, so an outage degrades instead of breaking.

③ Profile defaults — arithmetic, no model

Medians and frequencies over committed history fill only the slots the message left unsaid. Explicit input always wins; nothing applies below 3 orders; whatever is applied is named in the reply.

④ Swiggy workers — two, concurrent

asyncio.gather over Food and Instamart, each wrapped in wait_for(2.5s). A timeout returns partial results plus a warning and the session goes DEGRADED — never blank. Instamart is skipped entirely when the message never asked for it.

⑤ Output guardrails

Budget check (warn, never reject — the group trims it themselves) · dietary tag validation · placeholder filter · source-attribution check. Portion and cost arithmetic happens here, not in a worker.

⑥ Persist

Session and cart written to PostgreSQL. Host token hashed, guest token stored, status ACTIVE or DEGRADED.

Outcomes

✅ Resolved

Both verticals answered, budget respected → ACTIVE

⚠️ Resolved with warnings

Over budget or dietary mismatch → ACTIVE + warnings the canvas renders

🟠 Degraded

A vertical timed out or failed → DEGRADED, partial cart, add items manually

❌ Blocked

Injection detected → no session, HTTP 400
